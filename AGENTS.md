# AGENTS.md — правила для агентов в этом репозитории

## Что это за проект

`google-keyword-ai-mcp` — CLI (`gkai`), MCP-сервер (`google-keyword-ai`) и
Claude-скил для сбора и анализа поискового спроса Google. Четыре провайдера
данных, три сценария исследования, персистентные запуски, скоринг и
кластеризация. Подробная карта — в `CLAUDE.md`, архитектура — в
`docs/architecture.md`.

## Команды

Локально ничего не ставить: интерпретатор и зависимости живут в Docker.
Все команды запускать от своего непривилегированного юзера. Любая команда
проекта — это `uv run --all-extras <что-то>` внутри контейнера:

```bash
docker run --rm -v "$PWD":/app -w /app --user "$(id -u):$(id -g)" \
  -e UV_CACHE_DIR=/app/.uv-cache -e HOME=/tmp \
  ghcr.io/astral-sh/uv:python3.14-bookworm-slim \
  uv run --all-extras pytest -q
```

Меняя последнюю строку, получаешь остальные: `ruff check .`,
`ruff format --check .`, `mypy`, `gkai --help`.

⚠️ `--all-extras` обязателен: без него `uv run` ставит только основные
зависимости, а тесты провайдеров Google Ads и Search Console падают на сборе
с `ModuleNotFoundError`. Окружение синхронизируется само, отдельный
`uv sync` не нужен.

Полный прогон, эквивалентный CI (он же — минимум перед коммитом):

```bash
docker run --rm -v "$PWD":/app -w /app --user "$(id -u):$(id -g)" \
  -e UV_CACHE_DIR=/app/.uv-cache -e HOME=/tmp \
  ghcr.io/astral-sh/uv:python3.14-bookworm-slim \
  bash -c 'uv sync --all-extras -q && uv run ruff check . \
    && uv run ruff format --check . && uv run mypy && uv run pytest -q'
```

CI гоняет то же самое на 3.12 и 3.14 (`.github/workflows/ci.yml`), поэтому
код обязан работать на обеих: нижняя граница объявлена в `requires-python`.

⚠️ Проверяя обе версии подряд, давай каждой СВОЁ окружение и свой кеш
(`-e UV_PROJECT_ENVIRONMENT=/tmp/venv312 -e UV_CACHE_DIR=/app/.uv-cache-312`).
Один общий `.venv` на два интерпретатора даёт полсотни падений в тестах,
которые выглядят как настоящая несовместимость с 3.12, а на деле это
перемешанное окружение: в изоляции те же тесты зелены.

## Чего делать нельзя

- **Менять `pyproject.toml` и `uv.lock` ради обхода проблемы.** Набор и версии
  зависимостей проверены на совместимость. Не хватает библиотеки — сначала
  доложи, а не добавляй молча. Обходить объявленную несовместимость
  (`--no-deps`, `--force-reinstall`, вендоринг, подмена тулчейна) запрещено:
  несовместимость — повод остановиться, а не повод найти лазейку.
- **Трогать `tests/fixtures/trends/`.** Это боевые ответы Google Trends,
  снятые вживую 2026-09-02, включая намеренно разреженный случай. Они —
  golden-фикстуры: если формат Google изменится, тест обязан покраснеть.
- **Добавлять секреты, токены и ключи в репозиторий** — ни в код, ни в тесты,
  ни в фикстуры, ни в логи. Креды провайдеров читаются только из окружения и
  файлов вне дерева (`docs/privacy.md`).
- **Писать сетевые тесты, ходящие в живой Google.** Провайдеры мокаются через
  `respx`; живой прогон — ручная проверка человеком, не часть набора.
- **Ронять паритет CLI и MCP.** Оба отдают один и тот же конверт
  (`schema_version`, `data`, `warnings`, `errors`, `completeness`,
  `completeness_reason`, `run_id`) — модель `Envelope` одна, но сериализуют её
  по-разному: CLI зовёт `to_wire()`, MCP возвращает `Envelope`, и его
  раскладывает SDK. Совпадение результата держится не на общем коде, а на
  тестах в `tests/test_mcp_parity.py` — их и смотри, меняя форму ответа.
  Union-типы в возвращаемых значениях MCP-инструментов
  запрещены: SDK заворачивает такой ответ в лишний ключ и паритет ломается.
- **Делать MCP-инструменты асинхронными.** Функции инструментов синхронные
  намеренно — SDK уносит их в рабочий поток, а `async def` выполнил бы
  блокирующие обращения к БД и сети прямо в event loop.

## Изменение схемы БД

Миграции forward-only через `PRAGMA user_version` (без alembic), см.
`src/google_keyword_ai/storage/migrations.py`. Поднимаешь версию — пиши шаг
миграции и тест, который проверяет апгрейд со СТАРОЙ версии с данными, а не
создание пустой базы с нуля.

## Документация

Значимое изменение поведения — строка в `CHANGELOG.md`. Меняешь структуру или
архитектуру — обнови `CLAUDE.md`. Добавляешь команду CLI или MCP-инструмент —
`tests/test_docs.py` покраснеет, пока она не описана в
`.claude/skills/researching-google-keywords/reference/cli.md` и `docs/mcp.md`
соответственно; это сделано нарочно, чтобы документация не расходилась с кодом.

- Источник требований — файл спеки, указанный в промпте. Он имеет приоритет

  `index.lock` — это не твоя ошибка и не повод искать обход: остановись и
  доложи в `blocked_reason`.

## Команды

- Установка зависимостей: НЕ НУЖНА. Интерпретатор и все зависимости уже лежат
  в клоне: `.venv/` (Python 3.14.3, поставлен принимающим до запуска). Ничего
  не устанавливать.
- Сборка: не требуется — это библиотека и два CLI-фасада.
- Тесты: `.venv/bin/python -m pytest -q` (из корня клона, БЕЗ Docker).
- Линтер / типы: `.venv/bin/python -m ruff check .`,
  `.venv/bin/python -m ruff format --check .`, `.venv/bin/python -m mypy`.

⚠️ Docker в этом окружении агенту недоступен: песочница обнуляет
дополнительные группы процесса, `/var/run/docker.sock` виден как
`nobody:nogroup`, любой вызов docker падает с `permission denied`.
Не пытайся обойти это — прогон в контейнере делает человек на приёмке.

⚠️ Сети тоже нет: не резолвится даже прокси. Зависимости уже установлены в
дереве, ставить ничего не нужно и не получится. Если чего-то не хватает —
остановись и доложи, не собирай урезанную версию на том, что оказалось под
рукой.

## Чего делать нельзя

- Обходить объявленную несовместимость зависимостей (`--no-deps`,
  `--force-reinstall`, вендоринг, подмена тулчейна, отключение проверок).
  Несовместимость — повод остановиться и доложить, а не повод найти лазейку.
- Повторять упавшую команду третий раз, не изменив подхода.
- Класть тестовые зависимости в прод-реквайременты.
- Добавлять секреты, токены и ключи в репозиторий.

## Карта репозитория

- `src/google_keyword_ai/cache.py` — кеш ответов провайдеров поверх таблицы
  `cache_entries`; это главный файл вехи.
- `src/google_keyword_ai/config.py` — `Settings` (pydantic-settings, префикс
  переменных `GKAI_`).
- `src/google_keyword_ai/storage/` — движок SQLite, прагмы, миграции. В этой
  вехе НЕ меняется, но читать полезно: приём с флипом `autocommit` на
  DBAPI-соединении взят оттуда.
- `src/google_keyword_ai/usecases/` — сценарии; фасады CLI и MCP зовут только
  их. Образец для нового `usecases/cache.py` — `usecases/runs.py`.
- `src/google_keyword_ai/cli/main.py` — команды Typer; группы заводятся через
  `app.add_typer(...)`.
- `src/google_keyword_ai/envelope.py` — единый конверт ответа.
- `tests/` — pytest; сетевых тестов не писать, провайдеры мокаются `respx`.
- `docs/specs/` — спеки вех, включая спеку этого прогона.
