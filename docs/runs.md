# Запуски исследований

Запуск сохраняет состояние `gkai research`, чтобы результат можно было
посмотреть, экспортировать или продолжить после сбоя. Обычного кеша для этого
недостаточно: процесс может остановиться после внешнего запроса, но до записи
успешного ответа в кеш. Лимит или деньги уже потрачены, а повторный запуск не
знает об этом.

Запись запуска содержит идентификатор, сценарий и цель, рынок, состояние,
версии приложения и парсера, снимок бюджета, безопасный снимок конфигурации,
временные метки, результат или ошибку. Отдельно хранятся упорядоченные стадии:
их состояния, число попыток и контрольные точки.

Отпечаток стадии — первые 32 шестнадцатеричных символа SHA-256 от
канонического JSON с именем стадии, целью, рынком, бюджетом и seed keyword.
При `resume` завершённая стадия годна для пропуска, только если у неё есть
контрольная точка, отпечаток совпадает и версии приложения и парсера не
изменились.

Смена версии приложения или парсера делает все контрольные точки запуска
устаревшими. Продолжение начинает вычисления заново и добавляет объяснение в
предупреждения: смешивать результаты, полученные разными версиями кода или
разбора, небезопасно.

`gkai run resume <id>` продолжает тот же запуск и переиспользует годные
контрольные точки. `gkai run rerun <id>` создаёт новый идентификатор и заново
выполняет то же исследование, не меняя исходную запись.

Снимок конфигурации формируется штатным маскированием настроек. Значения
токенов, client secret и refresh token в базу не записываются.
