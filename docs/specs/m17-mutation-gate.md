**Репозиторий:** `google-keyword-ai-mcp` · **Веха:** `M17-MUT` · **Дата:** `2026-09-06`
· **Исполнитель:** **Codex** · **Файл спеки в репо:** `docs/specs/m17-mutation-gate.md`

**Почему именно Codex.** Боевой код и тесты вехи M17 писал **Grok**. Правило проекта:
мутации по чужому коду гоняет ПРОТИВОПОЛОЖНЫЙ исполнитель — автор кода и автор теста
к нему разделяют одно заблуждение, и оно попадает в обе половины сразу. Эта веха
существует ровно затем, чтобы независимо доказать: новые тесты M17 действительно
ловят поломку боевого кода, а не просто зелёные.

## Контекст

Веха M17 внесла потолок страниц (`google_ads_max_pages`) в ключ кеша Ads-идей и
разрешила класть в кеш ОБРЕЗАННЫЙ ответ вместе с флагом `truncated` и причиной.
Дифф вехи: `src/google_keyword_ai/providers/google_ads.py` (+59/−21) и
`tests/test_google_ads_provider.py` (+141) — шесть новых тестов, один переименован
и переписан, один старый удалён.

Прошлая веха закрыта отчётом `report.json` со всеми `pass`. Это ничего не говорит
о КАЧЕСТВЕ новых тестов: тест, который не падает ни при какой поломке боевого кода,
проходит приёмку так же уверенно, как настоящий. Мутационный прогон — единственный
способ отличить одно от другого.

**Формулировка вехи.** Для каждой мутации: сломать боевой код в ОДНОМ месте →
прогнать ИМЕННО тот новый тест, который обязан это заметить → он обязан упасть на
своей строке ассерта → мутация откатывается → дерево байт-в-байт как было.

**Выживший мутант — дыра в ТЕСТАХ, а не находка в боевом коде.** Если мутант выжил,
боевой код НЕ правится: докладываешь, какой именно тест не заметил поломку.

5. **Все шесть мутантов убиты** названными тестами, и каждый — на ожидаемой строке

6. **Мутации изолированы:** M2 оставляет зелёным тест M1, M3 — тесты M4/M5 и

   M6 — тест M1-второй. Это проверено прогоном, а не рассуждением: значит новые
   тесты не дублируют друг друга, каждый ловит своё.
7. **Одно исключение из правила «падение на своей строке ассерта».** Мутация M1
   убивает `test_a_pre_cap_cache_entry_is_missed_not_read` не ассертом, а

8. **Инфраструктура клона (ПРЕДПОЛОЖЕНИЕ, вживую не проверено).** Свежий клон

### Контракт обвязки

Обвязка сама накладывает мутацию, гоняет тест, откатывает и возвращает **0, когда
мутант УБИТ**. Голая команда «тест обязан упасть» здесь запрещена: приёмщик
перезапускает команды на чистом дереве, где мутации уже нет, и получил бы `rc=0`
при любом качестве тестов.

CLI:

- `python tests/mutation_gate.py` — прогнать ВСЕ мутации, напечатать таблицу,
  выйти `0` тогда и только тогда, когда убиты все.
- `python tests/mutation_gate.py --only <ID>` — одна мутация.
- `python tests/mutation_gate.py --self-check` — БЕЗ мутаций: прогнать на чистом
  дереве все тесты, названные в таблице (и «должен упасть», и «должен остаться
  зелёным»), выйти `0`, если все зелёные.

Обязательные свойства:

1. **Таблица мутаций — данные в самом файле** (id, путь к файлу, якорь-фрагмент,
   замена, список «обязан упасть» с ожидаемой строкой, список «обязан остаться
   зелёным»). Никаких мутаций «на лету» и никакой генерации по AST.
2. **Якорь обязан встречаться РОВНО ОДИН раз.** `text.count(anchor) != 1` —
   немедленный ненулевой выход с внятным сообщением, БЕЗ записи в файл.
3. **Откат — из сохранённых В ПАМЯТИ БАЙТОВ, в `finally`.** Не `git checkout`, не
   `git stash`: git восстановил бы «как в индексе», затерев чужие правки и скрыв
   собственную ошибку обвязки.
4. **sha256 файла до и после.** Не совпали — громкое сообщение и ненулевой выход,
   даже если мутант был убит.
5. **Отказ стартовать на изменённом файле:** перед первой мутацией обвязка считает
   sha256 боевого файла и сверяет с `expected_sha256`, записанным в самой таблице
   мутаций. Не совпал — ненулевой выход, ничего не трогая.
   ⚠️ **git внутри обвязки не использовать вообще** (`git status`, `git diff`,
   `git checkout`): обвязка запускается в образе
   `ghcr.io/astral-sh/uv:python3.14-bookworm-slim`, где git НЕ УСТАНОВЛЕН —
   проверено исполнителем 06.09.2026. Проверка через sha256 сильнее: она не
   зависит ни от индекса, ни от того, закоммичена ли чужая правка.
   `expected_sha256` на базовом коммите клона —
   `626a5e94c0ce427df0f635fe413a3c46776c410425420af3c0fb17c8f1c1abb0` (снято
   постановщиком; сверь сам `sha256sum src/google_keyword_ai/providers/google_ads.py`
   и, если разошлось, останавливайся по контракту, а не подгоняй константу).
6. **Запуск тестов:** `sys.executable -m pytest -q -p no:cacheprovider --tb=line <nodeids>`
   из корня репо. `-p no:cacheprovider` — чтобы прогон не оставлял `.pytest_cache`.
7. **Вердикт «убит»** = КАЖДЫЙ тест из «обязан упасть» отмечен `FAILED`, И для
   каждого строка исходника по позиции из `--tb=line` содержит ожидаемую подстроку,
   И КАЖДЫЙ тест из «обязан остаться зелёным» прошёл. Иначе — «выжил».
   Сверять по подстроке ИСХОДНОЙ СТРОКИ, а не по номеру: номера поедут от любой правки.
8. **Печать по каждой мутации:** `M1 KILLED by <nodeid> at <файл>:<строка> -> <текст строки>`
   либо `M1 SURVIVED (<что пошло не так>)`. Итоговая таблица — в конце.
9. Никаких `|| true`, `--no-deps`, подмены окружения и «пропустить, если не вышло».

## Критерии приёмки

Команды даны от корня клона. Везде — обёртка из `AGENTS.md`; в отчёт идёт ровно
та строка, которую ты выполнил. Обозначим общий префикс (в `report.json`
подставляй его целиком, без сокращений):

```
DK = docker run --rm -v "$PWD":/app -w /app --user "$(id -u):$(id -g)" \
     -e UV_CACHE_DIR=/app/.uv-cache -e HOME=/tmp \
     ghcr.io/astral-sh/uv:python3.14-bookworm-slim
```

- **AC-001 — самопроверка обвязки: на ЧИСТОМ дереве все названные тесты зелёные.**
  Без этого «мутант убит» ничего не значит: тест мог быть красным и до мутации.
  `$DK uv run --all-extras python tests/mutation_gate.py --self-check`

- **AC-002 — M1 убит** (потолок убран из ключа идей).
  `$DK uv run --all-extras python tests/mutation_gate.py --only M1`

- **AC-003 — M2 убит** (потолок на единицу меньше).
  `$DK uv run --all-extras python tests/mutation_gate.py --only M2`

- **AC-004 — M3 убит** (возвращён запрет кешировать обрезанное).
  `$DK uv run --all-extras python tests/mutation_gate.py --only M3`

- **AC-005 — M4 убит** (флаг обрезки теряется в кеше).
  `$DK uv run --all-extras python tests/mutation_gate.py --only M4`

- **AC-006 — M5 убит** (причина обрезки теряется в кеше).
  `$DK uv run --all-extras python tests/mutation_gate.py --only M5`

- **AC-007 — M6 убит** (потолок протёк в ключ historical).
  `$DK uv run --all-extras python tests/mutation_gate.py --only M6`

- **AC-008 — полный прогон гейта: все шесть убиты, таблица напечатана.**
  Выход `0` только если ни один мутант не выжил и все откаты сошлись по sha256.
  `$DK uv run --all-extras python tests/mutation_gate.py`

- **AC-009 — после всех прогонов боевые файлы не изменены.**
  `git diff --quiet -- src/google_keyword_ai/providers/google_ads.py tests/test_google_ads_provider.py`

- **AC-010 — обвязка проходит гейты качества репо** (она лежит в `tests/`, значит
  её видят и `ruff`, и строгий `mypy`).
  `$DK bash -c 'uv run --all-extras ruff check . && uv run --all-extras ruff format --check . && uv run --all-extras mypy'`

- **AC-011 — полный набор тестов зелёный** (новый файл не ломает сбор и ничего не
  импортирует лишнего).
  `$DK uv run --all-extras pytest -q`

- **AC-012 — рабочее дерево чистое, всё закоммичено** (артефакты отчёта исключены).
  Пустой вывод обязан проверяться КОДОМ ВОЗВРАТА: голый `git status` выходит нулём
  и на грязном дереве, то есть доказывает ровно ничего.
  `bash -c 'set -euo pipefail; test -z "$(git status --porcelain -- . ":(exclude)report.json" ":(exclude)report-blocked.md")"'`

## Контракт отчёта

В корне клона — `report.json`, ровно по одной записи на каждый `AC-001…AC-012`:

```json
{"criteria": [{"id": "AC-001", "status": "pass|fail|blocked",
               "command": "<команда-доказательство целиком>",
               "rc": 0, "note": "<что вышло, коротко>"}]}
```

`command` — та самая строка, которую ты выполнил (с раскрытым `$DK`), а не её
пересказ: приёмщик перезапускает её сам. Заявленный `pass` без реально выполненной
команды считается провалом вехи целиком.

Если что-то `blocked` — рядом `report-blocked.md`: что именно не вышло, какая
команда, какой вывод, чего не хватило.

  боевой код и существующие тесты; запускать что-либо в чужих tmux-сессиях.

## Контракт на невыполнимое

Наткнулся на несовместимость — **остановись и доложи**. Обходить запрещено:
никаких `|| true`, `--no-deps`, `--force-reinstall`, подмены интерпретатора,
правки `pyproject.toml`/`uv.lock` ради того, чтобы прогон позеленел, и никакого
«пропущу этот мутант, остальные же убиты». Несовместимость — повод остановиться,
а не повод найти лазейку.

Отдельно: **если мутант ВЫЖИЛ — это не повод править тест или боевой код.** Ставь
критерию `fail`, в `note` пиши, какой тест не заметил какую поломку, и заканчивай
прогон. Решение, чинить ли дыру в тестах, принимает владелец.

Если якорь мутации не нашёлся или встретился дважды (кто-то тронул файл) — тоже
стоп: это значит, что дерево не то, под которое написана спека.

## Стыки с соседними вехами

- **M16** (`m16-ads-max-pages`) ввёл сам потолок `google_ads_max_pages` и флаг
  `truncated`. Мутация M2 бьёт по строке `if pages_read >= max_pages:`, написанной
  в M16, — но убивает её НОВЫЙ тест M17, и это осознанно: проверка «поднятый
  потолок дочитывает пропущенные страницы» держится именно на этой арифметике.
- **M17** (`m17-ads-cache-page-cap`) — предмет вехи. Его спека лежит в
  `docs/specs/m17-ads-cache-page-cap.md` той же ветки; читать её полезно для
  замысла, но критерии там свои и здесь не повторяются.
- **Search Console** уже кладёт свой потолок (`daily_row_cap`) в ключ кеша —
  M17 привёл Ads к тому же контракту. Мутационного гейта у GSC нет; если владелец
  захочет такой же, это ОТДЕЛЬНАЯ веха, в эту не втягивать.
- Обвязка `tests/mutation_gate.py` задумана переиспользуемой: следующая веха
  дописывает в таблицу свои мутации, а не заводит второй скрипт.
